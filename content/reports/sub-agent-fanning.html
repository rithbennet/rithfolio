Bottom line

  1. Cost. The whole thread cost $147.09 at API list prices: Claude $117.88 (Opus orchestrator $90.17 = 61% of all spend; ten Sonnet sub-agents $27.71 = 19%) plus GPT-6.1-Sol testers $29.21 (20%). Both plans are flat-rate, so this is an equivalent, not a bill.
  2. Delivered. 58 findings (9 P1, 30 P2, 19 P3). At tester close 43 were fixed and re-verified, 8 partial, 7 open; follow-up commits targeted 6 of those 7 open items (not re-tested by the testers). 65 commits reached staging (12,489 added, 1,809 removed, 220 files). Median finding-to-live-fix time: 20 min.
  3. Value. Testers found a finding for about $0.50. The 8 Sonnet coder commits are 76% of all changed lines for 19% of spend. The costliest item is the Opus orchestrator re-reading its own context: cache reads were 78% of its cost and its context grew from 29k to 897k tokens.
  4. Caching. 98.9% of all input tokens were cache reads. The same tokens uncached would have cost $1,947 instead of $147 (92% less).
  5. Plans. The four testers used 12 points of the Codex Pro Lite weekly meter (21% to 33%, plus or minus 1 for rounding). Claude hit its 5-hour session limit at 01:15 MYT after about $80 of API-equivalent usage in 3.4 h; the orchestrator was shut out while the testers were still finishing. The exact Max-plan % is not logged; check /usage.
  6. Waste. Roughly $19 (13% of spend) was avoidable: tester polling $8.52, orchestrator wake-ups that did nothing $4.86, and the cache rebuild after the idle gap $5.52. Not counted: two accidental full test runs that wiped staging webhook audit rows.

Which agent type paid best

  • GPT testers: $0.50 per finding, 20% of spend, 58 findings of which 9 were P1. Best discovery value per dollar; but $8.52 (29%) of their spend was polling.
  • Sonnet coders: 8 commits = 76% of changed lines for 19% of spend, 12 min each on average, all running in isolated worktrees in parallel with the testers.
  • Scouts: two research runs for $0.69 in total: cheap, and they kept exploration out of the orchestrator's context.
  • Opus orchestrator: 61% of spend for routing, merging, small fixes (57 commits averaging 62 changed lines), deploys and live verification. Fully loaded it is the most expensive per commit only because it also carries everything else.

Was Sonnet a good trade for the coders?

  • Same tokens at Opus 5.5 prices: $37.94 vs $27.71 actual, so Sonnet saved $10.23 (27%), not the 50% the output prices suggest.
  • Why: 63% of sub-agent cost was cache reads, priced identically ($0.20/M) on both models. The lever for sub-agents is context size, not model tier.
  • Quality, honestly: no controlled comparison exists. All 8 coder commits landed as single commits and the bulk-booking, saved-address, resume-payment and cancel/rebook features passed the testers' recheck. But 6 of 8 later had a follow-up fix commit touching the same files (vs 26 of 57 orchestrator commits). Coder commits are about 23x larger, so this is confounded.

08What worked and what did not

What worked

  • Parallel testers plus a shared event board. 781 board events, 58 findings, 9 P1; the first P1 landed 2 minutes after launch and the first fixes were live at 23:51 MYT. Median finding-to-live 20 min.
  • Worktree coders in parallel. 8 isolated worktrees, one commit each that the orchestrator cherry-picked onto staging, 12 min median; they account for 76% of changed lines for 19% of spend.
  • 1-hour cache on the orchestrator avoided about $43 of rewrites estimate.
  • Live verification by the orchestrator after the testers left: 42 preview-browser calls (49 in the whole thread) drove the /dev courier controls to check follow-up work on staging; the return-guard fix was seen moving a parcel returning to Returned through a signed webhook (review doc).
  • Cost data is trustworthy. Orchestrator cost reproduces Claude Code's own total to 0.00%, sub-agents to 0.6%.

What did not

  • Context kept growing. 29k to 897k tokens, no compaction. Phase-2 cache reads cost $26.17; at a 100k-token context they would be about $3.20 estimate.
  • Session limit. 16 rejected prompts; orchestrator unavailable while testers finished; 7 items open at close.
  • Polling. $8.52 (29% of tester spend), 83 sleep calls across the four.
  • Orchestrator wake-ups. 81 notifications (66 board events, 15 sub-agent completions) started 69 turns; 37 produced no tool call and cost $4.86, each re-reading the whole context.
  • Two accidental full test runs at 00:23 and 00:43 MYT ran DB-backed integration tests against the shared staging database and deleted the Delyva webhook audit rows. Both commands were vitest run $(...) with a substitution that matched no files, so the filter vanished and the whole suite ran (119 and 109 s). The orchestrator disclosed it on the board at 00:45 MYT.
  • Wrong brief. The brief told the buyer testers a fixed code would verify signup; it does not on that route. They stalled for about 7 minutes (tokens only $0.74) until corrected, though both reported a genuine P1: a silent signup failure.
  • Preview host dropped once. DEV logged BLOCKED at 23:50 MYT (no automation host) and was back after 2.5 min; the orchestrator relayed a courier step through its own tab meanwhile. Also 6 API overload errors (529) within 34 s, auto-retried.
  • Shell-heavy orchestration. It edits and reads through shell commands (565 Bash calls vs 4 Read/1 Edit): a path-matching heuristic counts 558 read-like calls over 176 files, and 81 files were read three or more times heuristic. Each read stays in context for the rest of the thread.

09Recommendations for the next fan-out

Each one cites the number that motivates it. Savings are estimates unless stated.

  1. Make waiting free: wake testers on events, not on a timer.Polling cost $8.52 (29% of tester spend); the two buyers sent 263 board-only requests. Give each tester a blocking watcher that returns only when a line addressed to it is appended (the orchestrator already used one: 66 Monitor events), read incrementally (tail -n +N) and sleep 3 to 5 minutes between checks when nothing is pending. Potential saving up to about $9 of $29.
  2. Cap the orchestrator's context at phase boundaries.Cache reads were 78% of orchestrator cost. Start a fresh session with a written hand-off when the testers finish (here, at the idle gap) instead of carrying 702k tokens forward. Phase-2 reads would drop from $26.17 to about $3.20 at a 100k context (saving about $23 minus the hand-off cost) and the $5.52 rebuild disappears.
  3. Route by context size and role, not just model tier.Sonnet saved only 27% over Opus for the coders because cache reads cost the same on both. Keep Sonnet (or lower) for scoped coders, scouts and verification; keep scoped tasks short (12 min median worked), pass file paths in the brief and avoid dumping files into the prompt. Use Opus for orchestration judgement only.
  4. Spend reasoning effort where it changes decisions.Reasoning was 46% of tester output but only about $2.59 (9% of tester cost); output was 8% of orchestrator cost. Dropping effort will not move the bill much; cutting turns and context will. Keep xhigh for the orchestrator's merge and diagnosis steps; try high or medium for scripted testers.
  5. Keep 1-hour caching for the orchestrator, 5-minute for short sub-agents.The 1-hour TTL was worth about $43 here (14 pauses of 5 to 60 minutes). Sub-agents ran in tight loops where 5 minutes is enough. After a gap over an hour nothing helps: plan a hand-off rather than a resume.
  6. Protect shared state before running tests.Two accidental full runs hit the staging database. Never build a test command from an unguarded $(...); pass explicit paths or add --passWithNoTests semantics, run tests with a throwaway database URL, and block tests/integration when the env points at staging.
  7. Dry-run the brief.One wrong line in the brief cost both buyer testers about 7 minutes. Have one agent execute the setup steps before launching four.
  8. Watch the plan meter during fan-out.The 5-hour limit hit at about $80 of priced usage in 3.4 h with testers still running. Check /usage before launching, stagger launches, and leave headroom so the orchestrator is still available while testers finish; here the last findings waited 4 h 46 min for it.
  9. Cheaper verification.366 VERIFIED board events were mostly acknowledgements; only 24 findings have a recheck that reads as a pass. Ask for one structured recheck per finding after each deploy (ID, commit, PASS or FAIL, evidence path), and let the orchestrator run the cheap live checks itself with the dev controls.

How the numbers were made

  • Claude: one usage record per message.id (Claude Code writes one JSONL line per content block, and in sub-agents some lines hold partial output counts, so the line with the largest output is used). Main = 681 deduplicated calls; sub-agents = 609.
  • Codex: the last cumulative token_count per rollout; per-request records give the polling split. output_tokens includes reasoning tokens.
  • Validation: at Claude Code's own snapshot (01:51 MYT) it reported $54.68 for Opus and $15.78 for Sonnet; this script gets $54.68 and $15.68.
  • Phases: everything after the report request (Tue 06 Oct 08:51 MYT) is excluded. Phase 1 = before the resume at 06:01, phase 2 = after.
  • Findings: the board has 58 unique IDs; status is read from each tester's closing table with a few manual calls where a headline word hides a residual (SELLER-11, SELLER-12, C-SG-2, DEV-6, C-MY-1, C-MY-5, C-MY-9, C-MY-12 treated as partial).
  • Time-to-fix: first deploy-queue event that lists the ID, then the next confirmed live deploy of that or a later commit.

Caveats and data not available

  • Cost is list-price equivalent, not billing. No Claude Max percentage is logged anywhere; no Codex credit balance was used (has_credits: false).
  • Estimates (marked) rest on assumptions: weekly allowance from integer percent points; 5-hour allowance from one data point; TTL and context counterfactuals assume the same turns.
  • The orchestrator file-read count is a heuristic: it edits through shell commands, so path matching mixes edit-test loops with true re-reads. Compared with re-reading a 0.7M-token context every turn, individual file reads are a small cost.
  • Claude Code's cost snapshot lists $0.026 of Haiku 4.5; those requests are not in the transcripts and are left out.
